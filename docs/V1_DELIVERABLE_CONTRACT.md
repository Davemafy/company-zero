# Universal V1 Deliverable Contract

Company Zero product requests use `v1Mode`. Every accepted input converges toward a concrete Version 1 deliverable.

## Invariants

- Ambiguity is handled with reversible assumptions, not mandatory setup interrogation.
- Research, planning and organization synthesis support the deliverable; they are not the deliverable unless explicitly requested.
- The built-in Company Zero Studio is available to product-mode outcomes without an additional API key.
- Missing external capabilities are recorded as `system_capability_gap` and do not become a user-facing connection request by default.
- User interruption is reserved for genuine authority/account/approval boundaries.
- Studio output is persisted as a real `artifact` with inspectable files.
- External-world success is never fabricated. A V1 can be useful while external actions remain unavailable.
- The UI projects the latest artifact as Version 1 and exposes preview/download where supported.

## Runtime path

`input -> goal contract -> deliverable contract -> world/strategy/org -> Studio V1 and/or real capabilities -> artifact -> evidence -> revision`

The existing durable queue, organization revisions, Governor, approvals, evidence and provider runtime remain intact.
